<h1 id="0회차--프로젝트-주제-선정">0회차 | 프로젝트 주제 선정</h1>
<h2 id="1-이번-프로젝트를-시작한-이유">1. 이번 프로젝트를 시작한 이유</h2>
<p>Java/Spring 기반 백엔드 개발을 공부하면서 한 가지 고민이 생겼다.</p>
<p>단순히 기능을 하나씩 구현하는 것에서 끝나는 것이 아니라,
<strong>하나의 서비스가 실제로 어떻게 설계되고 운영되는지 경험해보고 싶었다.</strong></p>
<p>특히 최근에는 금융 IT와 AICC(Artificial Intelligence Contact Center)에 관심을 가지고 관련 내용을 공부하고 있다.</p>
<p>금융 시스템을 공부하면서는 Transaction, Idempotency, 정합성, 거래 이력과 같은 개념을 접했고,
인턴십에서는 기존 상담 시스템과 IPCC에서 AICC로 전환되는 과정을 살펴보면서 상담 시스템이 단순히 고객의 질문에 답하는 프로그램이 아니라는 점에 관심을 가지게 되었다.</p>
<p>고객의 요청을 받으면</p>
<blockquote>
<p>고객 식별 → 데이터 조회 → 업무 처리 → 결과 반환 → 이력 관리</p>
</blockquote>
<p>와 같은 여러 과정이 연결된다.</p>
<p>그래서 이번에는 이런 흐름을 작은 규모의 프로젝트로 직접 구현해보기로 했다.</p>
<hr />
<h2 id="2-처음에는-자산관리-서비스를-생각했다">2. 처음에는 자산관리 서비스를 생각했다</h2>
<p>처음 생각했던 아이디어는 비교적 단순했다.</p>
<p><strong>개인의 금융자산을 등록하고 관리하는 서비스</strong>였다.</p>
<p>예를 들어,</p>
<ul>
<li>예금·적금 계좌 등록</li>
<li>주식 보유 내역 등록</li>
<li>거래 내역 관리</li>
<li>예금·적금 이자 계산</li>
<li>주식 수익률 계산</li>
<li>현재 자산 조회</li>
<li>매일 자산 현황 알림</li>
</ul>
<p>등을 구현하는 것이다.</p>
<p>여기에 Telegram을 연결하면 매일 정해진 시간에</p>
<blockquote>
<p>현재 총 자산은 얼마이고, 어제보다 얼마나 변했는지</p>
</blockquote>
<p>확인할 수도 있다.</p>
<p>백엔드 공부를 하기에는 충분히 좋은 주제라고 생각했다.</p>
<p>하지만 한 가지 의문이 있었다.</p>
<blockquote>
<p><strong>그런데 이 서비스를 굳이 내가 만들어야 하는 이유는 무엇일까?</strong></p>
</blockquote>
<p>단순 자산관리 기능만 구현한다면 이미 비슷한 서비스가 많다.</p>
<p>그래서 기능을 추가하는 대신 <strong>문제를 다시 정의해보기로 했다.</strong></p>
<hr />
<h2 id="3-자산관리에서-금융-상담으로">3. 자산관리에서 금융 상담으로</h2>
<p>자산관리 서비스에서 사용자는 자신의 데이터를 직접 조회한다.</p>
<pre><code class="language-text">내 자산
  ↓
조회
  ↓
이자 / 수익률 계산
  ↓
결과 확인</code></pre>
<p>하지만 금융 서비스에서 고객이 실제로 하는 요청은 조금 더 다양하다.</p>
<p>예를 들어,</p>
<blockquote>
<p>이번 달 적금 이자는 얼마예요?</p>
</blockquote>
<blockquote>
<p>제가 가지고 있는 주식 수익률을 알려주세요.</p>
</blockquote>
<blockquote>
<p>지난달에 어떤 거래를 했는지 보여주세요.</p>
</blockquote>
<p>이런 질문에는 단순히 미리 저장된 정보를 보여주는 것 이상의 처리가 필요하다.</p>
<p>고객의 금융 데이터를 조회하고,
필요한 계산을 수행하고,
그 결과를 고객에게 전달해야 한다.</p>
<p>그리고 상담 시스템의 관점에서는 여기서 끝나지 않는다.</p>
<pre><code class="language-text">고객 문의
   ↓
문의 유형 파악
   ↓
고객 데이터 조회
   ↓
금융 업무 처리
   ↓
결과 생성
   ↓
고객 응답
   ↓
상담 이력 저장</code></pre>
<p>이 흐름을 직접 구현해보고 싶어졌다.</p>
<p>그래서 프로젝트의 방향을 <strong>개인 자산관리 서비스 → 금융 상담 백엔드</strong>로 변경했다.</p>
<hr />
<h2 id="4-프로젝트-주제">4. 프로젝트 주제</h2>
<p>이번 프로젝트의 주제는 다음과 같이 정의했다.</p>
<blockquote>
<p><strong>금융 고객의 상담 요청을 실제 금융 데이터 조회와 업무 처리까지 연결하는 작은 컨택센터 백엔드 시스템</strong></p>
</blockquote>
<p>처음부터 실제 금융기관 수준의 시스템을 만들겠다는 의미는 아니다.</p>
<p>오히려 작은 규모로 범위를 제한하고,</p>
<p><strong>고객의 질문이 들어왔을 때 백엔드에서는 어떤 일이 일어나는가?</strong></p>
<p>를 직접 구현해보는 것이 목표다.</p>
<hr />
<h2 id="5-핵심-흐름">5. 핵심 흐름</h2>
<p>프로젝트의 핵심 흐름은 다음과 같다.</p>
<pre><code class="language-text">[고객]
   │
   │ 금융 문의
   ▼
[상담 채널]
   │
   ▼
[상담 요청 처리]
   │
   ├── 문의 유형 확인
   │
   ├── 금융 데이터 조회
   │
   ├── 계산 / 업무 처리
   │
   ▼
[응답 생성]
   │
   ▼
[고객에게 응답]
   │
   ▼
[상담 이력 저장]</code></pre>
<p>처음에는 Telegram을 상담 채널로 사용한다.</p>
<p>Telegram을 사용하는 이유는 Telegram 자체가 프로젝트의 핵심이기 때문이 아니다.</p>
<p>웹 화면이나 별도의 프론트엔드를 처음부터 만드는 것보다
<strong>상담 요청을 보내고 결과를 받는 채널을 빠르게 구성할 수 있기 때문</strong>이다.</p>
<p>따라서 구조적으로는 다음과 같이 생각하고 있다.</p>
<pre><code class="language-text">                 ┌─ Telegram
                 │
고객 → 상담 채널 ┼─ Web
                 │
                 └─ AICC / Voice
                        │
                        ▼
                상담 업무 백엔드
                        │
             ┌──────────┼──────────┐
             ▼          ▼          ▼
          금융조회    계산/업무    상담이력</code></pre>
<p>이번 프로젝트에서는 우선 Telegram만 구현하고,
나중에 다른 채널로 확장할 수 있도록 생각해볼 예정이다.</p>
<hr />
<h2 id="6-금융-프로젝트로서-무엇을-구현할까">6. 금융 프로젝트로서 무엇을 구현할까?</h2>
<p>MVP에서는 금융상품을 너무 많이 다루지 않기로 했다.</p>
<p>우선 다음 두 영역으로 제한한다.</p>
<h3 id="예금·적금">예금·적금</h3>
<ul>
<li>계좌 등록</li>
<li>입금/출금 내역</li>
<li>금리 등록</li>
<li>이자 계산</li>
<li>거래 내역 조회</li>
</ul>
<h3 id="주식">주식</h3>
<ul>
<li>보유 종목 등록</li>
<li>매수/매도 내역</li>
<li>평균 매수가 계산</li>
<li>현재가 입력</li>
<li>평가금액 계산</li>
<li>수익률 계산</li>
</ul>
<p>처음부터 증권사 API를 모두 연결하는 것도 목표로 하지 않는다.</p>
<p>우선은 직접 데이터를 등록하거나 테스트 데이터를 사용해
<strong>금융 업무 로직 자체를 먼저 구현</strong>한다.</p>
<p>이후 기본 기능이 완성되면 증권 API 연동을 검토할 예정이다.</p>
<hr />
<h2 id="7-백엔드에서-중요하게-볼-것">7. 백엔드에서 중요하게 볼 것</h2>
<p>이번 프로젝트에서 단순히 CRUD 기능만 만드는 것은 피하려고 한다.</p>
<p>특히 금융 시스템을 공부하면서 알게 된 개념들을 실제 코드에 적용해보고 싶다.</p>
<h3 id="transaction">Transaction</h3>
<p>예를 들어 거래를 처리할 때</p>
<pre><code class="language-text">거래 기록 저장
+
계좌 상태 변경</code></pre>
<p>중 하나만 성공해서는 안 된다.</p>
<p>둘 다 성공하거나, 문제가 발생하면 함께 되돌아가야 한다.</p>
<hr />
<h3 id="idempotency">Idempotency</h3>
<p>동일한 요청이 네트워크 문제 등으로 여러 번 들어왔을 때</p>
<pre><code class="language-text">입금 요청 1회
입금 요청 1회
입금 요청 1회</code></pre>
<p>가 실제로 3번 처리되는 문제가 발생하지 않도록
중복 요청을 어떻게 처리할지 고민해볼 예정이다.</p>
<hr />
<h3 id="batch--scheduler">Batch / Scheduler</h3>
<p>매일 정해진 시간에 금융 데이터를 계산하고
Telegram으로 리포트를 보내는 작업도 구현한다.</p>
<pre><code class="language-text">매일 08:00
   ↓
자산 조회
   ↓
이자 / 수익률 계산
   ↓
Daily Report 생성
   ↓
Telegram 전송</code></pre>
<p>단순히 <code>@Scheduled</code>를 사용하는 것에서 끝내지 않고,
중복 실행이나 실패가 발생했을 때 어떻게 처리할지도 생각해볼 예정이다.</p>
<hr />
<h3 id="상담-이력">상담 이력</h3>
<p>고객의 요청과 응답을 저장한다.</p>
<pre><code class="language-text">RECEIVED
   ↓
PROCESSING
   ↓
RESOLVED</code></pre>
<p>처리하지 못한 요청은 이후 확장 단계에서</p>
<pre><code class="language-text">ESCALATED</code></pre>
<p>상태로 관리할 수 있도록 설계한다.</p>
<p>이 부분을 통해 단순 챗봇이 아니라 <strong>상담 업무의 상태를 관리하는 백엔드</strong>를 만들어보려고 한다.</p>
<hr />
<h2 id="8-ai는-처음부터-넣지-않는다">8. AI는 처음부터 넣지 않는다</h2>
<p>처음에는 AI를 사용하지 않을 예정이다.</p>
<p>이유는 단순하다.</p>
<p>이번 프로젝트에서 먼저 확인하고 싶은 것은</p>
<blockquote>
<p><strong>사용자의 요청이 실제 금융 업무 로직과 어떻게 연결되는가?</strong></p>
</blockquote>
<p>이기 때문이다.</p>
<p>예를 들어 처음에는</p>
<pre><code class="language-text">이번 달 이자 얼마야?
        ↓
이자 조회 명령
        ↓
InterestService
        ↓
DB 조회
        ↓
이자 계산
        ↓
응답</code></pre>
<p>과 같이 명확한 구조로 만든다.</p>
<p>그 다음 자연어 처리를 추가한다면,</p>
<pre><code class="language-text">이번 달 적금에서 내가 받을 이자는?
        ↓
Intent Classification
        ↓
INTEREST_INQUIRY
        ↓
InterestService
        ↓
금융 데이터 조회
        ↓
응답</code></pre>
<p>처럼 기존 업무 로직 위에 AI를 연결할 수 있다.</p>
<p>즉, <strong>AI가 금융 업무 로직 자체를 대신하는 구조가 아니라 고객의 자연어 요청을 기존 업무 API에 연결하는 구조</strong>를 생각하고 있다.</p>
<hr />
<h2 id="9-이번-프로젝트에서-얻고-싶은-것">9. 이번 프로젝트에서 얻고 싶은 것</h2>
<p>이 프로젝트의 목표를 단순히 금융 관련 서비스 하나 만들기라고 생각하지 않는다.</p>
<p>지금까지 공부한 내용을 하나의 흐름으로 연결해보는 것이 더 큰 목표다.</p>
<pre><code class="language-text">Java / Spring
      ↓
MyBatis / SQL
      ↓
금융 도메인
      ↓
Transaction / Idempotency
      ↓
상담 업무 Flow
      ↓
Contact Center
      ↓
AI 연계</code></pre>
<p>그리고 프로젝트를 개발하면서 발생하는 오류나 설계상의 문제도 기록할 예정이다.</p>
<p>예를 들어</p>
<ul>
<li>DB 정합성 문제</li>
<li>Transaction 처리</li>
<li>중복 요청</li>
<li>Scheduler 중복 실행</li>
<li>외부 API 실패</li>
<li>데이터 불일치</li>
<li>예외 처리</li>
<li>로그를 통한 장애 추적</li>
</ul>
<p>등을 직접 경험하고 해결해보려고 한다.</p>
<p>그래서 이 프로젝트는 단순한 결과물보다는</p>
<blockquote>
<p><strong>기획 → 설계 → 구현 → 장애 발생 → 원인 분석 → 개선</strong></p>
</blockquote>
<p>의 과정을 기록하는 프로젝트로 만들고 싶다.</p>
<hr />
<h2 id="10-일단-여기까지-만든다">10. 일단 여기까지 만든다</h2>
<p>처음부터 너무 많은 것을 구현하지 않기 위해 범위를 다음과 같이 나눴다.</p>
<h3 id="mvp">MVP</h3>
<ul>
<li>금융 계좌/자산 등록</li>
<li>거래 내역 관리</li>
<li>이자 계산</li>
<li>주식 수익률 계산</li>
<li>Transaction</li>
<li>Idempotency</li>
<li>상담 이력</li>
<li>Telegram 상담</li>
<li>Daily Report</li>
<li>Scheduler</li>
</ul>
<h3 id="이후-확장">이후 확장</h3>
<ul>
<li>KIS API 연동</li>
<li>실시간/자동 시세 조회</li>
<li>자연어 Intent 분류</li>
<li>상담원 이관</li>
<li>상담 통계</li>
<li>관리자 화면</li>
</ul>
<h3 id="공부한-뒤-추후-적용을-위해-고려해-볼-것">공부한 뒤 추후 적용을 위해 고려해 볼 것</h3>
<ul>
<li>Kafka</li>
<li>Redis</li>
<li>CQRS</li>
<li>Event Sourcing</li>
<li>Saga</li>
<li>Transactional Outbox</li>
<li>STT/TTS</li>
<li>RAG</li>
<li>Voice AICC</li>
<li>Multi-region / DR</li>
</ul>
<p>공부하고 싶은 기술을 전부 넣는 것이 아니라,
<strong>현재 구현할 수 있는 범위와 앞으로 공부할 범위를 분리하는 것</strong>도 이번 프로젝트의 중요한 목표다.</p>
<hr />
<h2 id="11-앞으로의-계획">11. 앞으로의 계획</h2>
<p>다음 회차부터는 서비스 기획 단계부터 시작해보고자 한다.</p>
<p>먼저</p>
<p><strong>누가 이 서비스를 사용하고, 어떤 상황에서 어떤 요청을 하는가?</strong></p>
<p>를 정의해보려고 한다.</p>
<p>다음 글에서는 금융 고객을 하나의 가상의 사용자로 설정하고,</p>
<blockquote>
<p>고객 → 문의 → 상담 처리 → 금융 업무 → 응답</p>
</blockquote>
<p>으로 이어지는 <strong>페르소나와 User Journey</strong>를 작성해볼 예정이다.</p>
<p>그 다음에는 이 흐름을 실제 시스템 구조로 옮겨서
IA, Flow Chart, DB, API 설계까지 단계적으로 연결해보려고 한다.</p>
<hr />
<h2 id="마무리">마무리</h2>
<p>처음에는 단순한 자산관리 서비스를 만들려고 했다.</p>
<p>하지만 프로젝트를 시작하기 전에</p>
<blockquote>
<p><strong>이걸 왜 만드는가?</strong></p>
</blockquote>
<p>를 다시 생각해보면서 방향이 조금 달라졌다.</p>
<p>이번 프로젝트에서 만들고 싶은 것은 단순히 자산을 보여주는 서비스도,
처음부터 AI를 사용하는 금융 챗봇도 아니다.</p>
<p><strong>고객의 금융 문의가 실제 데이터 조회와 업무 처리로 이어지고, 그 결과가 다시 고객에게 전달되는 작은 금융 컨택센터 백엔드</strong>를 만들어보려고 한다.</p>
<p>얼마나 실제 금융 시스템과 비슷하게 만들 수 있을지는 아직 모르겠다.</p>
<p>대신 하나씩 직접 구현하면서
금융 서비스의 데이터와 업무 흐름이 백엔드에서 어떻게 연결되는지 확인해보려고 한다.</p>
