<h2 id="1-지난-글-이후">1. 지난 글 이후</h2>
<p>2회차에서는 카드 이중 결제 문의 하나를 따라가며 이관 패키지와 네 가지 결정(이관 기준, 인증 승계, 배정 방식, 챗봇 처리 범위)을 정했다. 다음 글로는 가상 은행 설계를 예고했다.</p>
<p>그 가상 은행 설계 글을 거의 다 써 놓고 멈췄다. 다시 읽어 보니 승인, 매입, 망취소, 원장 정정, 이자 산출까지 들어가 있었다. 이음은 컨택센터 백엔드이고, 가상 은행은 상담원이 볼 근거 데이터를 내주는 상대 시스템이다. 1회차에서도 &quot;실제 은행을 대신하는 작은 가상 은행&quot;이라고 적었는데, 글은 결제 시스템 설계 쪽으로 가 있었다.</p>
<p>세어 보니 이 시리즈는 0회차부터 설계 글만 네 번째였다. 1회차의 지켜야 할 네 가지도, 2회차의 배정 방식도 &quot;구현 회차에서 테스트로 확인한다&quot;로 끝나 있었다. 그래서 이번 주는 설계 글을 접고 카드 이중 결제 한 줄기를 끝까지 구현했다. 일정을 바꾼 이유는 저장소에 <a href="https://github.com/WontelliJ/ieum/blob/main/docs/adr/002-implement-thin-slice-early.md">ADR 002</a>로 남겼다.</p>

<h2 id="6-상담원-배정-조건부-update">6. 상담원 배정: 조건부 UPDATE</h2>
<p>2회차에서 상담원이 대기열에서 직접 가져가는 방식으로 정했고, 동시 수락은 조건부 UPDATE로 막기로 했다. 블로그 스터디 1주차에 회의실 예약 중복을 실험할 때 쓴 방식이다.</p>
<pre><code class="language-sql">UPDATE consultation
   SET status = 'CLAIMED', assigned_agent_id = #{agentId},
       claimed_at = #{now}, updated_at = #{now}
 WHERE consultation_id = #{id}
   AND status = 'HANDOFF_REQUESTED'</code></pre>
<p>상태를 먼저 바꾼 한 명은 1행을 받고, 나머지는 0행을 받는다. 0행이면 409로 응답한다.</p>
<pre><code class="language-java">int changed = consultationMapper.claim(consultationId, agentId, now);
if (changed == 0) {
    throw new ConflictException(&quot;이미 배정됐거나 대기 중이 아닌 상담이다: &quot; + consultationId);
}
eventRecorder.record(consultationId, EventType.ASSIGNED, Actor.AGENT, Map.of(&quot;agentId&quot;, agentId));</code></pre>
<p>배정에 성공하면 이관 패키지와 인증 승계 여부를 같이 돌려준다. 2회차 5-2대로 본인 확인 후 10분 이내면 상담원이 다시 묻지 않는다. 2회차에서 가정값으로 남긴 숫자들은 코드에 넣지 않고 <code>application.yml</code>로 뺐다.</p>
<pre><code class="language-yaml">ieum:
  policy:
    intent-failure-limit: 2      # 같은 용건 해석 실패 2회면 이관
    duplicate-window: 10m        # 같은 가맹점·금액 승인이 이 시간 안이면 중복 의심
    auth-inherit-validity: 10m   # 본인 확인 후 이 시간 안이면 상담원이 이어받음</code></pre>

<h2 id="8-트러블슈팅">8. 트러블슈팅</h2>
<h3 id="8-1-테스트가-실행되지-않았다">8-1. 테스트가 실행되지 않았다</h3>
<p>Windows PC에서 <code>gradlew test</code>를 돌리자 컴파일은 되는데 테스트가 하나도 실행되지 않았다.</p>
<pre><code class="language-text">오류: 기본 클래스 worker.org.gradle.process.internal.worker.GradleWorkerMain을(를) 찾거나 로드할 수 없습니다.</code></pre>
<p>처음에는 Gradle 설정 문제라고 생각했다. 그런데 못 찾는 클래스가 내 코드가 아니라 Gradle의 테스트 실행기였다. Gradle 홈 경로를 보니 <code>C:\Users\박진탁\.gradle</code>이었다. 사용자 폴더 이름에 한글이 있다.</p>
<p><code>GRADLE_USER_HOME</code>을 <code>C:\gradle-home</code>으로 바꾸자 테스트 실행기는 떴다. 그런데 이번에는 모든 테스트 클래스에서 같은 종류의 오류가 났다.</p>
<pre><code class="language-text">Caused by: java.lang.ClassNotFoundException: io.github.wontellij.ieum.handoff.HandoffFlowTest</code></pre>
<p>프로젝트도 <code>C:\Users\user\ieum</code> 아래에 있었고, 원인은 같았다. 폴더를 옮기지 않고 영문 경로로 정션을 만든 뒤 그쪽에서 실행했다.</p>
<pre><code class="language-bat">mklink /J C:\ieum %USERPROFILE%\ieum
set GRADLE_USER_HOME=C:\gradle-home
cd /d C:\ieum\apps\ieum-backend
gradlew.bat test</code></pre>
<p>이후 테스트가 모두 통과했다. 다시 겪지 않도록 README에 적어 두었다.</p>
<h3 id="8-2-이관-패키지에-정하지-않은-필드가-있었다">8-2. 이관 패키지에 정하지 않은 필드가 있었다</h3>
<p>시연 결과를 보니 승인 건마다 <code>&quot;approved&quot;: true, &quot;approvalCanceled&quot;: false</code>가 붙어 있었다. 정한 적 없는 필드다.</p>
<p>승인 건 record에 만든 판단용 메서드가 원인이었다.</p>
<pre><code class="language-java">public boolean isApproved() { return &quot;01&quot;.equals(status); }</code></pre>
<p>Jackson은 <code>isXxx()</code> 메서드를 속성으로 보고 JSON에 같이 내보낸다. 이관 패키지는 담을 것과 담지 않을 것을 정해 둔 데이터라서 필드가 이렇게 늘어나면 안 된다. <code>@JsonIgnore</code>를 붙였고, 패키지 JSON에 <code>approvalCanceled</code>가 없는지 보는 검사를 테스트에 추가했다.</p>
<h3 id="8-3-powershell-출력에서-한글이-깨졌다">8-3. PowerShell 출력에서 한글이 깨졌다</h3>
<p>시연 스크립트에서 봇 답변이 <code>ê°ë¨ OOì¹´í...</code>처럼 나왔다. 서버가 한글을 잘못 저장한 줄 알았는데, 같은 문장을 비교하는 테스트는 통과하고 있었다.</p>
<p>원인은 Windows PowerShell 5.1의 <code>Invoke-RestMethod</code>였다. 응답 헤더에 charset이 없으면 Latin-1로 읽는다. 스크립트가 응답 바이트를 UTF-8로 직접 읽게 바꾸자 정상으로 나왔다.</p>
<h2 id="9-해-보고-알게-된-것">9. 해 보고 알게 된 것</h2>
<ul>
<li>이벤트가 다 남아 있으면 이관 패키지는 그대로 따라 나온다. 이벤트를 하나 빠뜨리면 패키지에서도 빠진다. 원칙 ①을 지키려면 챗봇 단계의 모든 동작이 이벤트를 남기는지부터 봐야 한다</li>
<li>상담원 연결 안내 문구도 이관 전에 이벤트로 남겨야 대화 원문에 들어간다. 이벤트를 남기는 순서가 패키지 내용을 정한다</li>
<li>본인 확인 전에 상담원부터 찾는 고객도 있다. 처음 SQL은 PROCESSING에서만 이관하게 했다가 RECEIVED에서도 이관되도록 고쳤다</li>
<li>2회차에서 표로만 그렸던 가정값(해석 실패 2회, 중복 판단 10분, 인증 승계 10분)은 설정 파일 세 줄이 됐다</li>
</ul>
